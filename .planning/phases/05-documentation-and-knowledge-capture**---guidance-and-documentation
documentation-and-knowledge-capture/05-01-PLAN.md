Content sections (use bullet points and code examples, NO project-specific paths):

## Store Interface Pattern
- Define PromptStore interface with CRUD operations (Load, Save, Delete, List)
- Use context.Context as first parameter for all methods (future async support)
- Return nil for not-found cases (not errors) - simplifies caller error handling
- Deep copy returned prompts to prevent external mutation

## SemVer Versioning Pattern
- Use github.com/Masterminds/semver/v3 for version parsing
- Embed version in prompt ID (e.g., "agent@1.0.0")
- Auto-increment patch versions on save
- Support @latest alias for most recent version
- Tag-based alias resolution (scan files for matching tags)

## Thread-Safe In-Memory Store
- Use sync.RWMutex for concurrent read/write access
- Pre-allocate result slices for List operations
- Lazy initialize with sync.Once for expensive operations
- Nil-safe field access (check for nil slices before iteration)

## File-Based Persistence
- JSON format with one file per versioned prompt
- File naming: baseID@version.json
- Use syscall.Flock for exclusive write access (concurrent safety)
- Tag scanning for alias resolution instead of separate alias files
- Configurable storage path via environment variables

## Example Interface
```go
type PromptStore interface {
    Load(ctx context.Context, id string) *Prompt
    Save(ctx context.Context, prompt *Prompt) error
    Delete(ctx context.Context, id string) *Prompt
    List(ctx context.Context, filter ListFilter) []*Prompt
    ResolveAlias(ctx context.Context, alias string) *Prompt
    SetLatestAlias(ctx context.Context, id string) error
}
```

## DI Provider Pattern
- Create provider function that accepts config and returns PromptStore
- Support multiple backends (memory, file, etc.) via config selection
- Register provider with DI container (e.g., samber/do/v2)
- Use factory pattern for backend selection

## Testing Patterns
- Use table-driven tests for store operations
- Test concurrent access with goroutines and sync.WaitGroup
- Use mocks for testing store consumers
- Test both success and error cases
- Verify nil returns for not-found (not errors)
