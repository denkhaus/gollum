## What is Prompt Optimization?

Prompt optimization is the process of iteratively improving agent prompts using execution trajectory feedback. Each session makes agents better by gathering new facts from feedback and learning from their own trajectories.

Inspired by procedural memory in cognitive science: just as humans improve skills through practice, agents improve prompts through execution experience.

## Core Principles

- **Session-end optimization**: Optimization happens after execution completes, not during
- **Trajectory capture**: Record inputs, outputs, and intermediate states for analysis
- **Feedback collection**: Gather user feedback OR analyze session automatically
- **Version control**: Track prompt versions with SemVer for rollback and comparison
- **Iterative improvement**: Each session produces incrementally better prompts

## Optimization Strategies

### Gradient Descent (Multi-Phase Reflection)

- Reflection loop with structured analysis phases
- Think phase: Analyze what happened during execution
- Critique phase: Identify what went wrong or could be better
- Recommend phase: Propose specific prompt improvements
- Multiple iterations (configurable reflection steps)
- Single optimization pass using aggregated insights

Best for:
- Complex agents with many failure modes
- Scenarios requiring comprehensive analysis
- When prompt quality is critical

### Meta-Prompting (Single-Phase Combined)

- Combines reflection and update in single pass
- More efficient than gradient for simple cases
- Faster execution with less comprehensive analysis

Best for:
- Straightforward optimization needs
- Time-sensitive optimizations
- When trajectory quality is generally high

### Single-Shot (Direct Optimization)

- Direct prompt adjustment without reflection
- Fastest approach
- Minimal computational overhead

Best for:
- Minor prompt adjustments
- High-confidence scenarios
- Resource-constrained environments

## Trajectory Structure

Execution trajectories capture:
- Input messages sent to agent
- Output messages received from agent
- Intermediate states and tool calls
- Optional user feedback
- Original prompt used

## Feedback Patterns

### Explicit User Feedback

- Direct ratings (good/bad, 1-5 stars)
- Qualitative comments
- Correction examples
- Failure descriptions

### Automatic Feedback Analysis

- Success/failure detection
- Error pattern recognition
- Performance metrics
- Output quality heuristics

### Edit Feedback

- Specific suggested changes
- Targeted improvements
- Diff-based modifications

## Version Management

- Semantic Versioning (SemVer) for prompt versions
- MAJOR: Breaking changes to prompt structure
- MINOR: Backward-compatible improvements
- PATCH: Bug fixes and minor tweaks
- Alias support (@latest, @stable)
- Rollback capability for bad optimizations

## Store Abstraction

- Interface-based design allows multiple backends
- In-memory for testing and development
- File-based for persistence
- Cloud-based for production scaling
- Alias resolution for user-friendly references

## Integration Patterns

### End-of-Session Hook

```text
1. Agent session completes
2. Capture trajectory (messages, outputs)
3. Collect feedback (automatic or user-provided)
4. Run optimizer with trajectory + current prompt
5. Save optimized version with incremented version
6. Next session uses improved prompt
```

### Configuration

- Strategy selection (gradient/meta-prompt/single-shot)
- LLM provider choice (affects optimization quality)
- Reflection steps (for gradient strategy)
- Storage backend selection

## Best Practices

- Start with all three strategies available
- Use real-world data to learn which strategy works where
- Log optimization results for analysis
- Set minimum quality thresholds before accepting optimizations
- Keep prompt history for comparison and rollback
- Automate optimization as part of session lifecycle

## Common Pitfalls

- Over-optimization: Too many iterations can degrade prompt quality
- Feedback bias: User feedback may reflect personal preferences
- Evaluation lag: May take multiple sessions to see improvement
- Context loss: Over-optimization can remove important instructions
- Version sprawl: Too many minor versions make comparison difficult
