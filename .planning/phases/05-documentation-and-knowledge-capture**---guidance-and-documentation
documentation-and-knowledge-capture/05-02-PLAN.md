## Optimizer Strategy Pattern
- Define PromptOptimizer interface with Optimize method
- Implement multiple strategies (gradient, meta-prompt, single-shot) using same interface
- Use factory function (NewOptimizer) to create strategy-specific instances
- Validate config before creating optimizer instance
- Support enum-based strategy selection with string-to-enum mapping

## Trajectory Pattern
- Trajectory captures execution inputs, outputs, and intermediate states
- Reuse existing message types (don't duplicate from LLM library)
- Support optional feedback (string, structured, or edit feedback)
- Include original prompt for comparison

## Optimizer Types
```go
type Trajectory struct {
    Messages []Message
    Feedback interface{}
}

type OptimizerInput struct {
    Trajectory *Trajectory
    CurrentPrompt string
    Config OptimizerConfig
}

type OptimizerResult struct {
    NewPrompt string
    Version string
    ChangeDescription string
}
```

## Gradient Descent Strategy
- Multi-phase reflection loop (think -> critique -> recommend)
- Use LLM tool calling for structured reflection
- Run configurable number of reflection steps
- Aggregate insights across iterations
- Single optimization pass after reflection loop

## Meta-Prompt Strategy
- Single-phase approach combining reflection and update
- More efficient than gradient for simple cases
- Less comprehensive insights than multi-phase gradient

## Single-Shot Strategy
- Direct optimization without reflection loop
- Fastest approach for minor adjustments
- Use when trajectory quality is high

## LLM Integration Pattern
- Accept LLM client interface (not concrete implementation)
- Use agent framework for tool handling (not manual session management)
- Template-based prompt construction with placeholder variables
- Error handling for LLM failures
- Support multiple providers (Anthropic, OpenAI, Gemini)

## Configuration Pattern
- Use envconfig for environment variable loading
- Support strategy selection via config
- Configure reflection steps (min/max) for gradient strategy
- Provider selection via config
- Validate config bounds (min <= max)

## Factory Function
```go
func NewOptimizer(config OptimizerConfig, client LLMClient) (PromptOptimizer, error) {
    switch config.Strategy {
    case StrategyGradient:
        return newGradientOptimizer(config, client)
    case StrategyMetaPrompt:
        return newMetaPromptOptimizer(config, client)
    case StrategyPromptMemory:
        return newPromptMemoryOptimizer(config, client)
    default:
        return nil, ErrUnknownStrategy
    }
}
```

## Integration Helper Pattern
- Provide OptimizeAndSave orchestrator function
- Handle load -> optimize -> save workflow
- Auto-increment SemVer on save
- Return optimized result or error

## Testing Patterns
- Use mocks for LLM client
- Test each strategy independently
- Verify error handling for invalid config
- Test factory function with all strategies
- Use table-driven tests for strategy comparison
